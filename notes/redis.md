# Redis

## 类型用在哪

String 存 JSON 缓存和计数器；Hash 存对象适合改单个字段，比如购物车；ZSet 做排行榜；Set 做去重和共同关注。

## 缓存三大问题

- 穿透：查一个根本不存在的数据，每次都打到 DB。缓存空值（短过期）或者上布隆过滤器。
- 击穿：热点 key 过期那一瞬间大量请求压到 DB。重建缓存时加互斥锁，或者干脆逻辑过期。
- 雪崩：一批 key 同时过期。过期时间加个随机数错开，再配合限流兜底。

## 一致性

先更新数据库再删缓存。为什么是删不是更新：并发写的时候更新缓存可能把旧值写进去，删除是幂等的，下次读的时候自然回填。

## 分布式锁

手写版三件事：`SET key uuid NX EX 30` 一条命令加锁；业务放 try 里；释放用 lua 脚本判断 value 是自己的才删，防止误删别人的锁。

生产直接 Redisson，`tryLock` 传等待时间不传 leaseTime 会启用看门狗自动续期，不用操心业务没执行完锁先过期。

## 持久化

RDB 是快照恢复快但会丢最近一段数据，AOF 一秒刷一次盘丢得少文件大。生产基本是混合持久化。
